# PicPac · трек 2

Веб-приложение по прототипу Figma с обязательным путём от каталога до тестового заказа. React, TypeScript, CSS, локальный Node.js mock API. Реального списания денег нет.

## Запуск

Нужен Node.js 22.15 или новее. Распакуйте архив полностью и откройте START_PICPAC.cmd. Адрес: http://127.0.0.1:5174. Готовая сборка dist включена: скачивать npm-зависимости для обычного запуска не требуется. Остановка — STOP_PICPAC.cmd.

Ручной запуск из папки проекта: node server.mjs. Остановка ручного запуска — Ctrl+C.

Если уже работает старая версия PicPac без API, остановите её и запустите новую. Повторный запуск той же новой версии просто открывает приложение.

## Вход и основной путь

Тестовая учётная запись: demo@picpac.test. Пароль: PicPac2026! Можно продолжить как гость: имя и телефон понадобятся перед подтверждением заказа.

1. Откройте каталог и карточку шаблона. Тариф, формат и страницы меняют цену. Данные и цены приходят через GET /api/catalog из public/mock/catalog.json; при отсутствии сети используется сохранённый каталог.
2. Выберите фотографии с устройства либо добавьте 10 учебных файлов из тестовой галереи. Поддерживаются JPEG/PNG, до 12 МБ на файл, до 40 за одну загрузку.
3. В редакторе кнопка «Фото» открывает список: порядок меняется стрелками или перетаскиванием, снимок можно удалить. Развороты, макет, подпись и фон сохраняются вместе с фотографиями.
4. «Далее» запускает проверку проекта. Пустые области и отсутствующие файлы блокируют заказ. Недостаточное разрешение объясняется с размерами и dpi; можно заменить снимок либо явно подтвердить снижение качества. «Заполнить автоматически» размещает имеющиеся фото на всех разворотах, при необходимости повторяя их.
5. В корзине меняйте количество, название и применяйте PIC15. Выберите тестовый пункт выдачи, курьера или самовывоз. Для гостя укажите получателя.
6. Нажмите «Подтвердить без списания денег». Mock API присвоит номер. Если сети нет, заказ остаётся в устойчивой очереди и отправляется после подключения с тем же ключом операции.
7. Из истории откройте состав, расшифровку суммы, статусную ленту и обращения. Кнопка «Имитировать следующий этап» проводит тестовый заказ через модерацию, производство, готовность, передачу в доставку и завершение. У самовывоза этап передачи в доставку пропускается.
8. «Обратиться по этому заказу» открывает форму с выбранным номером. Обращение принимается mock API и остаётся в карточке именно этого заказа.

## Черновик, очередь, удаление

Фото хранятся в IndexedDB браузера. Настройки, порядок и черновик — в localStorage. Очередь заказов записывается до сетевого запроса и сохраняет снимок запроса с постоянным Idempotency-Key. Повтор после потери ответа возвращает существующий заказ; другой запрос с тем же ключом отклоняется.

Состояние mock API сохраняется в .picpac-data/state.json, переживает перезапуск сервера и исключено из выдаваемого архива и git. Там нет исходных фотографий: mock принимает конфигурацию и идентификаторы файлов; фото остаются на устройстве. API — учебная имитация серверного контура, не облачная типография.

В профиле доступно удаление загруженных фото и подтверждаемое удаление текущего аккаунта/тестовых данных. Удаление аккаунта очищает его заказы, обращения и сессии на mock-сервере, а также локальный черновик, очередь и файлы этого рабочего пространства. Для серверного удаления нужна сеть. Удаление фото из редактора физически удаляет файл из IndexedDB.

## Разработка и проверки

Установка: npm ci. Сборка: npm run build. Проверки логики и API: npm test. Приёмка в браузере: npm run test:browser. Дополнительная проверка входа и размеров: node tests/track2-auth-layout.mjs.

Для разработки сначала запустите node server.mjs, затем в другом терминале npm run dev. Интерфейс разработки будет на http://127.0.0.1:5175, запросы /api проксируются на 5174.

Браузерные тесты по умолчанию используют установленный Microsoft Edge в Windows. Другой Chromium можно указать через PICPAC_BROWSER. Проверка основного пути создаёт отдельного гостя и удаляет его данные в конце успешного сценария.

Основные файлы: src/Track2.tsx — обязательные сценарии; src/api.ts — HTTP и устойчивая очередь; src/workflow.mjs — проверка проекта и операции; src/photos.ts — файлы; src/App.tsx и src/screens — интерфейс; server/mock-api.mjs — API, цены, идемпотентность и статусы; public/mock/catalog.json — каталог и тарифы.

Граница реализации: реальная платёжная система, типография, push ОС, синхронизация оригиналов фото между устройствами и экспорт полиграфического PDF не подключены. Карта — схема из макета. Уведомления о статусах показываются внутри приложения. Продукт отдельный от курсового проекта «Атрибуция».

Изображения/SVG взяты из предоставленного макета Figma; Futura — из локальной установки пользователя. Исходный прототип: https://www.figma.com/proto/YWwew6c1ruXJJPfJoDLnPp/Фотопринт?starting-point-node-id=86%3A2422

## Каталог и лента · версия 2.1

Каждый чип каталога открывает собственный выпадающий список. Полоса фильтров листается пальцем, колёсиком и перетаскиванием мышью; доступна также прокрутка стрелками клавиатуры. Фильтры: тариф, формат, тема, страницы, количество фото, цена и сортировка. Выбор сохраняется при возврате из карточки; кнопка сброса снимает ограничения. Вместимость, число страниц и надбавка шаблона задаются в mock-каталоге, клиент и сервер учитывают одинаковые цены.

Размер, бумага и рамка в фотопечати тоже открываются отдельными списками.

На главной прокручивается только лента; шапка, категории и нижнее меню закреплены. Категории переводят к новинкам, идеям, отзывам и акциям. Добавлены идеи, полезная подсказка и переходы к шаблонам/фотопечати. При возврате на главную сохраняется место прокрутки в текущем сеансе.

Проверка новых взаимодействий: npm run test:ui.

## Обучение и котик · версия 2.2

После первого входа открывается необязательное обучение из четырёх шагов. Его можно пропустить, листать кнопками, свайпом и стрелками клавиатуры. Выбор запоминается в этом браузере. Повторный запуск — «Как работает PicPac» в профиле. Обучение не меняет проект и заказ.

При подготовке JPEG/PNG котик попеременно поднимает лапки. Прогресс отражает число обработанных файлов; 100% и штамп «СОХРАНЕНО» появляются после завершения записи в IndexedDB. Затем открывается редактор. Успешное изменение черновика сопровождается коротким «Сохранено, мяу», а подтверждённый mock-заказ — сообщением с его номером. При ошибке сохранения положительное подтверждение не показывается.

Кнопки «?» объясняют подбор шаблона и хранение черновика. Подсказки открываются нажатием, закрываются повторным нажатием, снаружи или Escape. Анимации учитывают системное предпочтение уменьшенного движения. Использованы исходные изображения котика из макета и собственные CSS-анимации; платные библиотеки и сервисы не подключались.

Проверка: npm run test:mascot. Семь сценариев включают первый вход, повтор/пропуск, подсказки, реальную загрузку 10 фото, успешное и неудачное сохранение, уменьшенное движение и экран 320 px. Для наблюдения промежуточной загрузки тест искусственно замедляет декодирование снимков.

Публикация и удалённый доступ пока не настроены: эта версия запускается локально.
