# Проверка требований трека 2

Проверено 12 ноября 2026 года на локальной готовой сборке в Windows, Node.js 22.15, Microsoft Edge. Реальные платёжные и производственные сервисы не использовались.

## Обязательные требования

- МП-01: каталог, продукты, варианты, цены и сроки — GET /api/catalog, источник public/mock/catalog.json. При недоступности сети используется сохранённая копия.
- МП-02: JPEG/PNG, до 12 МБ, сообщение с причиной при неподдерживаемом/нечитаемом файле; проверка разрешения с размерами в пикселях и dpi.
- МП-03: локально сохраняются продукт, фото, порядок, страницы, формат и настройки; файлы в IndexedDB, черновик в localStorage.
- МП-04: пересчёт опций, экземпляров, доставки и PIC15 на клиенте; mock API независимо пересчитывает сумму и отвергает устаревшую цену.
- МП-05: постоянный ключ сохраняется до запроса; сервер возвращает тот же заказ при повторе. Изменённый запрос с тем же ключом получает 409.
- МП-06: удаление фото из IndexedDB и подтверждаемое удаление аккаунта/тестовых данных на mock API и устройстве.

## Сценарии приёмки

- Вход с верными/неверными тестовыми реквизитами, отдельный гостевой режим с получателем перед заказом.
- Каталог → шаблон → 10 фото из тестовой галереи → изменение порядка → перезапуск без сети: порядок и настройки сохранены.
- Неподдерживаемый формат объясняется. Маленькое изображение вызывает предупреждение; продолжение блокируется до явного согласия. Пустой проект заказать нельзя.
- Количество, опции, промокод и способ получения меняют цену.
- Подтверждение без сети сохраняет запрос; несколько повторов и восстановление связи дают один номер заказа.
- Потеря ответа после создания заказа на сервере: повтор с тем же ключом не создаёт дубликат.
- История показывает состав, сумму и статус. Лента проходит принят → модерация → производство → готов → передан в доставку → завершён.
- Обращение из карточки заказа связано с его номером и открывается в этой же карточке.
- Удаление фото проверено по отсутствию записи в IndexedDB; после удаления аккаунта прежняя сессия получает 401.
- Проверены экран шириной 320 px и настольный вид без горизонтального переполнения.

Команды: npm test; npm run test:browser; node tests/track2-auth-layout.mjs. В репозитории сохранены проверочные сценарии, результаты кратко фиксируются в validation/.

## Границы

Mock API хранит тестовые заказы и обращения в локальном JSON, принимает метаданные проекта; оригиналы фото остаются в браузере. Это проверка учебного пути, а не интеграция с реальной типографией, платёжной системой или push ОС. Автоматическое заполнение разворотов реализовано; совместные альбомы, удаление размытых дублей, рекомендации и белорусская локализация не включены в обязательную версию.

## Версия 2.1: фильтры и лента

Проверены шесть новых браузерных сценариев: отдельные списки без общей формы; прокрутка полосы колёсиком и мышью; цена/сортировка/пустая выдача/сброс; сохранение выбора при возврате из карточки; прокрутка ленты при закреплённых шапке, категориях и меню; отдельные списки размера, бумаги и рамки в фотопечати. Основные 10 приёмочных сценариев и четыре проверки входа/компоновки повторно прошли. Цены шаблонов согласованы между каталогом, клиентом и mock API.

## Версия 2.2: обучение и обратная связь

Выполнены семь браузерных проверок нового поведения: обучение при первом входе с запоминанием завершения; повтор и пропуск; открытие и закрытие подсказок; анимация лап во время фактического декодирования и подтверждение после записи 10 фото; сообщение после успешного сохранения черновика; отсутствие положительного сообщения при принудительной ошибке localStorage; статичный котик при prefers-reduced-motion и отсутствие переполнения на 320 px. Скриншоты обучения, загрузки и сохранения просмотрены.

Повторно прошли 18 проверок логики/API (с учётом родительского теста), 10 основных браузерных сценариев, четыре проверки входа/компоновки и шесть проверок ленты/фильтров. Команда новых проверок: npm run test:mascot.
