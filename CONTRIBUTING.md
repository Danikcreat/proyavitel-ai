# Работа с тремя треками

| Область | Где изменять | Что проверить |
|---|---|---|
| Платформа и CRM | `platform/` | Контракты API и границы локального demo-режима |
| Приложение клиента | `picpac/` | `npm test`, `npm run build`, путь от каталога до заказа |
| AI-ассистент | `ai-service/` | Тесты и lint из `README.proyavitel.md` |
| Общая история проекта | `README.md`, `docs/` | Ссылки и соответствие заявлений работающему демо |

Изменения общего заказа согласовываются между треками: формат, сумма в копейках, идентификатор операции, параметры макета, доступ к файлам и статусы должны сохранять совместимость.

Не добавляйте ключи, реальные данные клиентов, рабочие appsettings, локальные базы, исходники фото покупателей и node_modules. Примеры конфигураций содержат только заглушки. Если меняются изображения PicPac, обновите `picpac/scripts/asset-manifest.json` и проверьте размер и Git blob SHA.

В описании изменения укажите проблему, итоговое поведение и выполненную проверку. Демонстрационные данные и интерфейсные заглушки обозначайте явно. Изменения в каналах уведомлений, ролевой модели и реальных записях backend требуют отдельной сквозной проверки.
